# 스태프 핫도그 — 작성 지침

> 새 회차를 만들 때 이 문서를 컨텍스트로 붙이고, 마지막 줄에
> **"이번 핫도그 주제: [주제명]"** 또는 **"이번 핫도그 자료: [URL]"** 을 추가한다.
> 동일한 톤·구조·디자인으로 생성한다.
>
> **중요 — 더 이상 EPUB가 아니다.** 과거엔 EPUB로 빌드했지만 지금은 이
> repo(Astro + Starlight) 안의 **마크다운 한 파일**이 곧 회차다. epub·JSON·
> 빌드 스크립트·epubcheck 다 없다. 콘텐츠는 `.md` 한 곳에서만 관리된다.

## 시리즈 정체성

**시리즈명**: 스태프 핫도그 (STAFF HOTDOG)

**한 줄 컨셉**: 스태프 엔지니어가 후배·동료에게 한 입에 떠먹여주는 개념 시리즈. 핫도그처럼 빨리 먹고 갈 수 있되, 본질은 정확하게.

**대상 독자**: "주니어"라고 명시하지 않는다. 경력 무관하게 누구나 한 번씩 짚고 갈 수 있는 보편적 톤을 유지한다. 받는 사람을 한정하는 순간 시리즈가 좁아진다.

**핵심 신조**:
- 외우지 말고 느껴라 — 숫자·개념을 직관으로 박는 게 목적
- 한 입에 한 통찰 — 한 회차는 한 가지 메시지에 집중
- 핵심만 살리고 나머지는 다이어트
- 숏츠 시대 — 여는 글·서론 없이 본문 바로 시작

## 회차 = 마크다운 한 파일

각 회차는 `src/content/docs/staffhotdog/bookNN.md` 파일 하나다. (`NN` = 영순위 2자리, `book04.md` 등)

이 한 파일이 두 가지로 렌더된다:
- **원문** `/staffhotdog/bookNN/` — Starlight 스크롤 문서
- **이북** `/staffhotdog/bookNN/?view=book` — 같은 페이지 위 페이지넘김 뷰
  (`public/staffhotdog-reader.js`가 본문을 CSS 컬럼으로 페이지네이션)

### 파일 골격

```markdown
---
title: '스태프 핫도그 #N — [주제]'      # 이북 표지 제목은 — 뒤의 [주제]에서 뽑힘
description: '[한 줄 부제]'              # 이북 표지 부제 = 이 값
sidebar:
  label: '#N — [주제]'
  order: N
banner:
  content: '<strong>초안</strong> · 본문은 다듬는 중입니다.'   # 완성되면 제거
---

<a class="ebook-launch" href="?view=book">📖 이북으로 보기</a>

## 1. [도입·핵심 통찰]
...본문...

## 2. [본격 전개]
...본문...

## 3. [실전·응용]
...본문...

## 닫는 글
...세 줄 요약 + 더 깊이 + 사인오프...
```

### 5블록 구조 (변하지 않음)

1. **표지** — **직접 쓰지 않는다.** 엔진이 `№ NN`(파일명) + `title`의 주제 +
   `description`(부제) + `em3s`로 자동 합성한다. frontmatter만 정확히 채우면 됨.
2. **1장 `## 1. ...`** — 도입·핵심 통찰. 왜 중요한가 + 시그니처 그림 1장.
3. **2장 `## 2. ...`** — 본격 전개. 여러 각도, 그림 3~5장.
4. **3장 `## 3. ...`** — 실전·응용. 손에 잡히는 예제, 코드 또는 계산.
5. **닫는 글 `## 닫는 글`** — 세 줄 요약 + 자료 3~4개 + 사인오프.

**헤딩 규칙**: 챕터는 `##`(h2), 챕터 안 소제목은 `###`(h3). `#`(h1)은 쓰지 않는다
(페이지 제목은 frontmatter `title`이 담당). 이북 목차·챕터 분할이 `##` 기준이다.

**닫는 글 형식 고정**:
- `<p>한 입 분량 끝. 정리는 세 줄.</p>` 로 시작
- 번호 매긴 핵심 세 줄 (`<ol>`)
- "이 세 줄이 머리에 남았다면 한 핫도그 잘 드신 거예요." 마무리
- `## 더 깊이 가고 싶다면` — 원전·실전·맥락 3가지로 분류 (혹은 본문 내 소제목)
- 사인오프:
  ```html
  <div class="closing">
    <div class="closing-mark">*&#160;*&#160;*</div>
    <p>스태프 핫도그 #N — [제목]<br/>다음 핫도그에서 만나요.</p>
  </div>
  ```

## 톤 가이드

**문장**:
- 짧은 호흡. 군더더기 빼기. 명사형 종결도 적절히 ("끝.", "병렬화의 출발점.").
- 친근하지만 무게 있게. 스태프 엔지니어가 말하는 톤.
- "~입니다/습니다"체 기본, 가끔 "~예요"로 가볍게.
- 영어 기술 용어는 그대로 ("MapReduce", "shuffle", "latency"). 굳이 한글화하지 않는다.

**삼가야 할 것**:
- 과도한 격식 ("안녕하세요, 오늘은…" 류 인사말 없음)
- 자기 비하 또는 자랑
- "주니어를 위한", "초보자도 쉽게" 같은 받는 사람 한정 표현
- 길게 늘어지는 도입부

**스타일 시그니처**:
- 비유 ("SQL이 MySQL이 아니듯, MapReduce도 Hadoop이 아니다")
- 대비 강조 ("외우지 마라. 느껴라.")
- 한 줄 takeaway를 인용구로 (`<blockquote>`)
- 핵심 단어 **굵게** 또는 *기울임*

## 본문 구성 요소 (마크다운 + HTML)

마크다운 본문 안에서 HTML을 그대로 쓸 수 있다. 헤딩만 마크다운(`##`/`###`)으로.

- **문단**: `<p>` 또는 그냥 빈 줄로 구분한 텍스트
- **코드 블록**: ` ```lang ... ``` ` 또는 `<pre><code>...</code></pre>`
- **인라인 코드**: `` `...` `` 또는 `<code>...</code>`
- **인용구**: `<blockquote>` 또는 `> ` — 한 줄 통찰
- **리스트**: `-` / `1.` 또는 `<ul>`/`<ol>` (항목 3개 이상일 때)

**Callout 박스** (시그니처):
```html
<div class="callout callout-{purple|blue|amber|teal|gray}">
  <p class="callout-title">제목 (선택)</p>
  <p>내용</p>
</div>
```
색별 의미는 회차마다 재할당하되, **한 회차 안에서는 일관성** 유지.

> 코드블록·콜아웃·표가 한 페이지를 넘으면 이북에서 자동으로 다음 장으로 흐른다.
> 이미지는 한 페이지 안에 들어가도록 높이가 제한된다. 작성자가 신경 쓸 것 없음.

| 이름 | 어두운 텍스트 | 옅은 배경 | 진한 라인 | 일반적 의미 |
|-----|-----------|---------|---------|----------|
| Purple | `#3C3489` | `#EEEDFE` | `#534AB7` | 메타·스펙·추상 |
| Blue   | `#0C447C` | `#E6F1FB` | `#185FA5` | 시작·입력·Map |
| Amber  | `#633806` | `#FAEEDA` | `#854F0B` | 중간 처리·Shuffle |
| Teal   | `#085041` | `#E1F5EE` | `#0F6E56` | 결과·Reduce·요약 |
| Gray   | `#1a1a18` | `#F1EFE8` | `#888780` | 기본·중립 |

회차마다 색의 의미는 주제에 맞게 재할당하되, 한 회차 안에서는 일관되게.
(콜아웃 클래스 `callout-purple/blue/amber/teal/gray` 모두 라이트·다크 양쪽에서 스타일됨.)

### 그림

**위치·참조**: PNG를 `public/staffhotdog/assets/NN/` 에 넣고, 본문에서 **절대경로**로 참조.
```html
<div class="figure">
  <img src="/tilmore/staffhotdog/assets/NN/fig_name.png" alt="설명"/>
</div>
```
`.figure`는 흰 배경으로 락(라이트·다크 공통) — 다이어그램 색 보존. 작성자가 CSS 만질 것 없음.

**왜 PNG인가**: 다크모드에서 SVG가 inversion 당하지 않도록 래스터로 박는다.

**SVG → PNG 렌더링 사양** (그림을 새로 그릴 때):
- viewBox 너비 `480` (좁게! 모바일에서 글자 크게)
- 출력 해상도 `1000px` (예: cairosvg `output_width=1000`)
- 첫 요소 `<rect width="480" height="..." fill="#ffffff"/>` — 흰 배경 락
- 폰트: 한글 `"Noto Sans CJK KR, Noto Sans KR, sans-serif"`, 코드 `"monospace"`
  - **monospace 안에 한글이 있으면 □로 깨진다.** 한글 포함 줄은 무조건 한글 폰트.
- 폰트 크기: 제목 22px / 본문 15~17px / 코드·숫자 강조 17~20px / 캡션 13~14px
- 색: 본문 `#1a1a18`, 부제·캡션 `#444441`, 박스 내부 강조는 해당 색 진한 변종
- 박스 stroke `1.5~2.5px` (얇으면 다크모드에서 안 보임)
- **한 그림 = 한 메시지.** 한 장에 욱여넣지 말 것. 차라리 두 장으로.

### 표지 — frontmatter로만

직접 HTML 표지를 쓰지 않는다. 이북이 다음으로 합성한다:
- `№ NN` ← 파일명 `bookNN.md`
- 제목 ← frontmatter `title`의 `—` 뒤 주제
- 부제 ← frontmatter `description`  (예: `#1` → "스펙과 구현, 그리고 한 줄 bash")
- 저자 ← `em3s` (고정)

## 렌더링·배포 (EPUB 빌드 대체)

- **소스**: `src/content/docs/staffhotdog/bookNN.md` 한 파일. JSON·생성기 없음.
- **이미지**: `public/staffhotdog/assets/NN/*.png`.
- **로컬 확인**: `npm run dev` → `http://localhost:4321/tilmore/staffhotdog/bookNN/`
  와 `?view=book` 둘 다 확인. (정적 빌드 확인은 `npm run build && npm run preview`)
- **배포**: `main`에 푸시하면 GitHub Actions가 자동 배포(GitHub Pages).
- **PWA/오프라인**: `scripts/gen-sw.mjs`가 prebuild/predev에서 `public/sw.js`를 생성해
  원문 페이지·이미지·엔진을 프리캐시한다. 새 회차 추가 시 자동 반영(권 id는 md 파일명에서).
- 사이드바·이북 권 선택기는 md를 추가하면 자동으로 잡힌다(`sidebar.order`로 순서).

## 새 회차 작성 워크플로우

1. **주제 + 자료 받기** — 사용자가 URL이나 키워드 던짐
2. **자료 fetch** — 외부 자료면 정확한 내용 확보
3. **3장 구조 제안 (1회 짧게)** — 핵심 메시지 한 줄 + 1·2·3장 각 한 줄, 사용자 OK.
   비유 단위·강조 포인트 한두 가지 확인. 길게 묻지 말 것.
4. **그림 설계** — 시그니처 1장(1장에) + 전개 3~5장(2장) + 실전 1장(3장). 합쳐 6~8장.
   PNG를 `public/staffhotdog/assets/NN/`에 저장.
5. **`bookNN.md` 작성** — frontmatter + 이북 버튼 + `## 1/2/3` + `## 닫는 글`.
6. **확인** — `npm run dev`로 원문과 `?view=book` 둘 다, 그림 한글 깨짐·글자 크기 점검.
7. **푸시** — `main` 푸시 → 자동 배포.

## 주의사항

신규(현재 구조):
- **표지를 직접 쓰지 마라.** frontmatter `title`/`description`만 정확히.
- **챕터는 `##`로 시작.** `#`(h1) 금지. 소제목은 `###`.
- **`<section>` 래퍼 쓰지 마라.** (옛 epub 잔재. 챕터는 평탄하게.)
- **이미지는 절대경로** `/tilmore/staffhotdog/assets/NN/...`.
- 본문 맨 위 `<a class="ebook-launch" href="?view=book">📖 이북으로 보기</a>` 유지.
- 콜아웃 색은 `purple/blue/amber/teal/gray`만 (스타일된 클래스).

그림(여전히 유효):
- **monospace + 한글 = □ 깨짐**. 한글 SVG text는 한글 폰트로.
- **viewBox 480 고수** (넓으면 모바일에서 글자 작아짐).
- **한 그림에 한 메시지**.

폐기(더 이상 신경 쓸 것 없음): EPUB3 빌드, mimetype/manifest, epubcheck,
`properties="svg"`, `&nbsp;`↔`&#160;`, build_epub_*.py — **전부 안 쓴다.**

## 시그니처 한 줄 자산

회차마다 *"한 줄로 표현하면 이거예요"* 식 시그니처 인사이트 한 줄을 만든다.
닫는 글·공유·다음 회차 회상에서 이 한 줄이 핵심.
- #1: "MapReduce는 스펙이다. Hadoop은 그 스펙의 한 구현체다."
- #2: "L1 캐시가 한 호흡이면, 대륙간 왕복은 인생의 한 챕터."
